# Decisions

Judgment calls made while building Felt Notes, and the reasoning. The brief
said to decide and document rather than ask — this is that document.

## Repo

- **This branch replaces the previous site content.** The repository carried
  an unrelated Next.js site (TerraNova); the Felt Notes branch is a dedicated
  feature branch, so the app lives at the repo root where the tooling expects
  it. The old site is untouched on its own branches.

## Scope and semantics

- **Heads-up equity only.** The equity calculator is hero vs. one hand/range.
  Multi-way Monte Carlo is easy to add but hard to *input* well on a phone,
  and all-in review spots are overwhelmingly heads-up. Better a sharp tool
  than a vague one.
- **Raise amounts are "to" totals.** `I 3bet 45` means "raise to 45". This is
  how live players actually speak, and it makes pot math unambiguous.
- **One `bb`-suffixed amount switches the whole hand to bb units.** Mixing
  units within a hand is a user error we soften: if stakes are known, bb
  results are converted to money for the stats; if not, the hand is excluded
  from money stats and counted as excluded.
- **Uncalled bets are refunded.** When a final bet is folded to, the uncalled
  portion returns to the bettor before the pot is awarded, exactly as in a
  real card room. Without this, "I bet 90, he folds" would inflate both pot
  and winnings.
- **Unknown results stay unknown.** If a hand ends with two players still in
  and no stated winner, we save it with a warning and keep it out of profit
  stats. Guessing the winner from shown cards would require an evaluator
  opinion about a hand the user may have misremembered — not worth the
  corruption risk.
- **Ambiguous pronouns resolve to the last aggressor, with a warning.** In
  multiway pots "he bets" is genuinely ambiguous; the last aggressor is the
  right guess most of the time, and the warning teaches the fix (name the
  seat).
- **Antes and run-it-twice are out of scope** for the parser v1; straddles
  (both as stakes and as an action) are in, because they're everywhere in
  live games.
- **Session profit = cash-out − total buy-in**, with add-ons folded into
  buy-in via the live-session card. Hand-level results deliberately do *not*
  feed the session ledger — you log a handful of interesting hands, not the
  whole session, so the ledger's source of truth is the cage, not the notes.
- **Deleting a session detaches its hands instead of deleting them.** Logged
  hands are the most expensive thing the user creates; nothing else should
  silently destroy them.

## Statistics honesty

- **Every rate ships with its numerator/denominator** (`3/5 hands`) and rates
  with zero opportunities render as `—`, never `0%`.
- **Leak flags gate on minimum samples** (5–40 depending on the rule). A flag
  that fires on four hands is noise wearing a costume. Below threshold the
  report says "no flags yet" and tells you to keep logging.
- **Hourly rate hides below 30 minutes of total play** — a 10-minute winning
  session extrapolates to comedy numbers otherwise.
- **VPIP-style stats are labeled as "of what you wrote down".** Live players
  log memorable hands; pretending this is a HUD sample would be lying with
  numbers.

## Technical

- **No `idb` dependency.** The schema is two object stores; a 100-line
  promise wrapper is clearer than a library and keeps the dependency tree at
  exactly react + react-dom.
- **Hand-rolled hash router.** Six routes, no nesting, works from `file://`
  and any static host subpath, and survives offline reloads trivially. A
  router library would be the heaviest thing in the bundle.
- **Hand-written service worker with build-time precache injection.** A tiny
  Vite plugin writes the hashed asset list into `sw.js` at build time, so the
  entire app (fonts included) is cached at install — offline works after the
  first visit, not after the user happens to browse every screen.
  vite-plugin-pwa/workbox would add ~100 dependencies to avoid ~60 lines.
  One real-world subtlety baked in: cache matches use `ignoreVary: true`,
  because static servers commonly send `Vary: Origin` and `crossorigin`
  script/style requests would otherwise never match the precached entries —
  found by running the offline checklist repeatedly, not by reading docs.
- **Seeded PRNG (mulberry32) in the equity engine** so tests are exact and
  reproducible; the UI worker seeds from the clock for variety.
- **Equity accuracy over speed tricks.** Plain 7-card evaluator + rejection
  sampling does 100k iterations in well under a second in a worker; lookup
  tables would complicate the code for speed nobody needs here.
- **Fonts are self-hosted woff2** (OFL-licensed: Big Shoulders Display,
  Public Sans, IBM Plex Mono), downloaded at build-authoring time and
  committed — zero runtime CDN requests, per the brief.
- **PNG icons are generated by a checked-in script (`scripts/make-icons.mjs`)** (procedural
  renderer + zlib PNG encoder) because the build environment had no
  rasterizer; the SVG sources remain canonical.
- **React 18 over 19**: no compiler features needed, maximum ecosystem
  stability for a public release.

## Design

- **Identity: card-room artifact.** Felt green-black base, off-white ink,
  $5-chip red used *only* for losses/warnings, bone/cream *only* for wins.
  All colors are custom properties in `src/styles/tokens.css`.
- **Type:** Big Shoulders Display (condensed industrial signage) for
  headings, Public Sans for body, IBM Plex Mono with `tabular-nums` for every
  number, money amount, and card. Numbers are the product.
- **The profit graph is hand-drawn SVG** — thin ink line, felt-textured
  pattern fill, hairline ledger rules, dashed zero line. No chart library.
- **Density over whitespace:** hairline-bordered panels, racing-form tables,
  a fixed bottom tab bar sized for thumbs at 360px. No gradients, no
  glassmorphism, no soft shadows, no emoji iconography (nav marks are
  typographic glyphs: § ✎ ♠ ♦ % ⇅).

## Verification

- 99 Vitest tests: 57 parser (the brief's 40+ scenarios), 20 equity
  (validated against known equities: AA vs KK ≈ 81.9%, AKs vs QQ ≈ 46%,
  AA vs random ≈ 85.2%, exact chop/drawing-dead boards), 22 stats/leaks/
  import-validation.
- `scripts/walkthrough.mjs` drives the built app through the full release
  checklist at 360px and 1440px: session → 5 hands (one deliberately
  malformed, fixed via the highlighted span) → hand-computed stat checks
  (showdown −$22 / non-showdown −$107) → end session → export → wipe →
  re-import → corrupted-file rejection → offline reload → zero console
  errors.
